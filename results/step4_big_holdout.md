# STEP 4 — 확장 홀드아웃 재평가 (결정적)

홀드아웃을 오버레이 없는 실주방 화재(DVIDS 공개도메인 + 소방서 실연)로 확장:
**fire 10→71, smoke 4→7, 정상 32→59.** dvids/northants는 같은 영상에 정상·화재가 다 있어 배경 누수 없음.

## 결과 (base vs v2, 큰 홀드아웃)

| 지표 | base(프롬프트만) | v2 파인튜닝 |
|---|---|---|
| fire 재현율 | 71/71 (100%) | 71/71 (100%) |
| 발연 3분류('smoke' 정확) | 42.9% | 28.6% |
| LEMONADE 정상 오탐 (오버헤드, 랜덤/hard) | 2.5% / 0% | 0% / 0% |
| **홀드아웃 정상 오탐 (스토브 클로즈업, 59장)** | **76.3%** | **94.9%** |

## 두 가지 큰 반전 (홀드아웃을 키워서야 보임)

### 1. 오탐 문제는 사실 심각하다 — 프레이밍 문제였다
이전에 "프롬프트로 오탐 해결됨(2.5%)"은 **LEMONADE 오버헤드 와이드샷** 기준이라 낙관적이었다.
실제 배포 프레이밍(**스토브 위 냄비/팬 클로즈업**)에선 base가 정상을 **76% 위험으로 오판**한다.
→ CCTV로 조리기를 감시하는 이 프로젝트의 **핵심 문제(오탐)는 실재하고 심각하다.** (프로젝트 전제 재확인)

### 2. 그런데 합성 파인튜닝은 오탐을 더 악화시킨다
v2는 스토브 정상 오탐을 76%→**95%로 악화**. 합성 불꽃을 전부 조리 배경에 얹어 학습한 탓에
모델이 "**스토브/팬 장면 = 위험**"으로 더 강하게 편향됐다. 발연 3분류도 43%→29%로 하락.
불은 여전히 다 잡지만(재현율 100%), 정작 필요한 **오탐 억제에서 파인튜닝이 역효과.**

## 결론 (방향)
- **문제는 진짜다**: 스토브 감시 프레이밍에서 base 오탐 76%. 여기가 프로젝트가 풀 값어치 있는 지점.
- **현재 합성 접근은 틀린 약**: 조리배경+합성불꽃만 학습 → "조리장면=위험" 편향 심화 → 오탐 악화.
- **진짜 필요한 학습 데이터**: "스토브 위 냄비, 불 없음 = 정상"을 대량으로. 다행히 이번에 받은
  실화재 영상들의 **발화 전(pre-ignition) 프레임이 바로 그 실 정상 데이터**다.
  → 영상 단위로 train/holdout을 나눠, **실 스토브 정상 + 실 화재**로 하이브리드 학습하는 게 정공법.
