# STEP 0 — 기본 Qwen2.5-VL-3B 화재 인식 베이스라인

파인튜닝 **안 한** 기본 `Qwen/Qwen2.5-VL-3B-Instruct`로 측정. 프로젝트 방향 결정용(HANDOFF.md 5절).

## 세팅
- 데이터: **D-Fire**(공개 실화재셋) test 샤드에서 화재 100 + 정상 100 = 200장
  - fire = 라벨에 불(class 1) 존재 / normal = 라벨 완전히 빔(불·연기 없음). 연기만 있는 이미지는 제외.
  - 재현: `scripts/step0_prepare_dfire.py` (seed 0) → `scripts/step0_baseline.py`
- 프롬프트: `"Does this image show a fire? Answer only 'fire' or 'normal'."`
- greedy(T=0), 양성 클래스 = fire.

## 결과 (양성 = fire)

| 지표 | 값 |
|---|---|
| 정확도 Accuracy | **0.785** |
| 정밀도 Precision | 0.708 |
| 재현율 Recall | **0.970** |
| **F1** | **0.819** |

혼동행렬:

| | pred fire | pred normal |
|---|---|---|
| **gold fire** | 97 (TP) | 3 (FN) |
| **gold normal** | 40 (FP) | 60 (TN) |

판독불가 0건(모델이 항상 `fire`/`normal` 한 단어로 답함).

## 해석 (숫자보다 중요)
- **불은 거의 다 잡는다 (Recall 0.97).** 야간의 작고 먼 불 3장만 놓침 → "화재 존재 감지"는 기본 모델이 이미 잘함.
- **약점은 오탐(Precision 0.71).** 정상 100장 중 40장을 화재로 오경보. 오탐 이미지는 **마른 언덕 + 옅은 연무·먼지가 있는 야외 CCTV** 장면 → 모델이 연무를 불/연기로 과잉 반응.
- **도메인 주의: D-Fire는 "야외 산불 감시 CCTV"** 데이터셋(언덕·주차장·야경)이다. 주방/조리 도메인과 시각적으로 완전히 다르다.
  → 이 F1 0.819는 **조리 맥락 능력을 측정한 게 아니다.** "주방 화재 감지" "김 vs 위험 연기 구분"은 여전히 미검증(해당 실 홀드아웃 없음).

## 방향 판단
- 기계적 기준(F1 < 0.85)만 보면 "파인튜닝 가치 있음 → 그대로 진행"이지만, **Recall 0.97**이 진짜 이야기다:
  기본 모델은 이미 명백한 불을 잘 잡는다. 파인튜닝으로 얻을 여지는 주로 **오탐 줄이기(정밀도)** 이며, 그마저 **조리와 무관한 야외 도메인**에서의 개선이다.
- 결론: **"단순 화재 유무 감지"는 태스크로 약하다**(HANDOFF 5절 A/B로 기운다). 다만 전환할 "어려운 조리 태스크"를 **무엇으로 검증할지(실 홀드아웃)** 를 먼저 확정해야 한다. 이게 없으면 프로젝트 규칙 7절(합성으로 학습·합성으로 평가 금지)에 걸린다.
